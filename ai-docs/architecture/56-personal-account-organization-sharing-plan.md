## 1. Область решения и authority

H — отдельная полоса доставки рядом с текущим E2E. [Norm53](./53-account-gateway-implementation-contract.md), SHA256 `66a2393e7a55f76df1a78281af44379d0b455a0770d82f34e587dcca284157b0`, остаётся единственным текущим контрактом D/E/F/G. Владелец явно разрешил планирование, канонический личный каталог stable `User.id`, несколько своих аккаунтов в нескольких org, org-owned аккаунты независимо от личных, единственный источник имени/auth, собственный RR UI, breaking reconnect вместо сложной миграции. Обязательные invariants: immutable owner/native identity нельзя преобразовывать; org detach и потеря роли дарителя затрагивают только соответствующую org; повторный attach не оживляет retired authority. Выбранный механизм этого последнего invariant: новый immutable binding ID, старый binding навсегда revoked (§5.2). Этот инженерный выбор проверен R1/R2 и техническим MAIN read, а не приписан отдельному указанию владельца о schema.

Принятая здесь минимальная политика H-V1: даритель должен оставаться действующим `owner|admin` каждой org; demotion до `member` или removal необратимо отзывает его личные grants этой org. Обычный member может пользоваться разрешённым binding через действующий repository/run policy, но не делиться своим каталогом и не изменять источник. H-V1 не включает offer/approve, ACL language, marketplace, org-to-org sharing, передачу источника, общую квоту разных продуктов или per-user deployment.

Отдельный продукт54 имеет самостоятельный admin-owned pool и deployment. ## 3. Минимальная модель продукта

```text
User U (stable RR User.id)
  canonical personal connection A -> one gateway account / current generation
    personal workspace P binding(A, P)
    organization X binding(A, X), immutable binding BX
    organization Y binding(A, Y), immutable binding BY
Organization X
  canonical org-owned connection D -> its independent gateway account
    binding(D, X)
```

`ProviderAccountConnection.id` — продуктовая canonical source identity; `gatewayAccountRef` — server-only logical gateway identity; native numeric ID/birth — только gateway/native. Binding — local usage, не аккаунт. Personal owner = `ownerUserId=U`, `ownerWorkspaceId=null`; org-owned = inverse. В org binding нет name, profile override, auth material, credential copy, upstream login/email, native ID. Canonical safe mirror name/profile/status хранится **один раз** в RR source row и читается join; gateway остаётся authoritative для auth epoch/profile/native mapping. Cache safe row не создаёт второй канонический источник.

Workspace ownership transfer в doc29 означает передачу прав на workspace, но не передачу личного account. Org-owned D остаётся workspace-owned после смены org owner. `U→V`, personal→org, org→personal, orgX→orgY conversion запрещены; новая связь требует fresh connection с новой immutable owner identity. Исторический source/ref не переиспользовать.

Canonical name владелец выбирает с предупреждением в форме: имя увидят разрешённые org. Org не получает email владельца; имя может содержать введённый им текст, поэтому продукт не обещает удалять email из произвольной label. Automatic label не берётся из email/provider subject. Дубликаты имён допустимы; identity никогда не определяется именем.

## 7. Distributed order, live checks и pinned execution

RR authority: stable owner/membership/binding/repo policy; gateway: immutable account epoch/generation/claim/capacity; native: protected credentials/physical birth/refresh. Общей transaction нет. RR commit local deny → remote fence/operation with same durable ID → matching readback/ACK CAS → safe final state; неопределённость не заменяется повторным create/inference. Lock order RR member/workspace authority (sorted) → source IDs → binding IDs → config/run. Existing connection→binding→authorization attachment order сохраняется; org attach/save/dispatch берут H member lock BEFORE source. Canonical owner mutation/revoke exact own ref берёт source→bindings, не блокирует consumer member row после source: current role читается обычным read; coordinated membership writer ждёт тот же source lock, затем атомарно retires rows. Так нет member→source/source→member deadlock и роль не может измениться без сопутствующего retirement. HTTP вне RR transaction.

**Attach**: server resolves live stable U and own source; scoped exact gateway GET verifies owner/profile/current epoch, then RR tx rereads U+X owner/admin, source no pending/active/same expected metadata revision, predecessor/history ACK. Creates BX with new ID=policySubject, counters1; gateway не хранит RR membership. Concurrent source operation locks A and pending pointer denies attach. Permission from stale picker/request context never sufficient.
