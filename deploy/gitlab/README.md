# ReviewRouter GitLab Runtime

This image is used by the GitLab control-project CI config generated by the
GitLab install API.

Build locally:

```bash
docker build -f deploy/gitlab/Dockerfile -t reviewrouter-gitlab-runtime:local .
```

Release publishing is done by `.github/workflows/gitlab-runtime-image.yml` after
the `CI` workflow succeeds on `main`, or by a manual dispatch from `main`.

The workflow publishes:

- `ghcr.io/777genius/review-router-gitlab-runtime:v1`
- `ghcr.io/777genius/review-router-gitlab-runtime:sha-<short_sha>`

It uses the workflow `GITHUB_TOKEN` with `packages: write`. Maintainer personal
tokens are not needed for release publishing.

After pushing, the workflow logs out from GHCR and pulls the stable tag without
credentials. If this anonymous pull check fails, make the GHCR package public in
GitHub Packages settings before using the generated GitLab CI config.

Request the control CI config:

```bash
curl -H "Authorization: Bearer $REVIEW_ROUTER_GITLAB_INSTALLER_ADMIN_TOKEN" \
  "$REVIEW_ROUTER_API_URL/api/gitlab/install/v1/control-ci-config"
```

The runtime keeps provider secrets in GitLab CI/CD variables and writes
`reviewrouter-findings.json` inside the GitLab job before publishing MR
discussions.
